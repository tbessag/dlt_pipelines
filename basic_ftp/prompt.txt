### Summary of the Problem

We are trying to run a **`dlt` (Data Load Tool) pipeline** to read CSV files from an internal Airbus **FTP server (Port 21)**.

While standard Python scripts (`ftplib` and `fsspec`) connect successfully, the **`dlt` pipeline consistently fails with `530 Login failed**`. The root cause has been identified as a parsing issue regarding the **semicolon (`;`)** inside the service account password.

### Technical Specifics

* **Target:** `ftsplus.airbus.corp` (Standard FTP, Port 21).
* **Library:** `dlt` (which wraps `fsspec`, which wraps `ftplib`).
* **The Conflict:** The password is `D6*bPb51SsYxW7;qEF+r`.
* The **`;`** is interpreted as a delimiter in connection URLs.
* If **Raw** in URL: The password is truncated at the `;`.
* If **Encoded** (`%3B`) in URL: `fsspec` sends the literal `%3B` to the server (it does not decode before sending), so auth fails.
* If **Passed via Dict** (`credentials={...}`): `dlt`/`fsspec` seems to ignore the dictionary or fails to merge it correctly when the URL scheme is provided.



### What has been validated (The "Control Group")

1. **Standard `ftplib` script:** Works perfectly. The server is accessible, and credentials are correct.
2. **Raw `fsspec` script:** Works **only** when bypassing the URL and passing `username`/`password` as keyword arguments directly to `fsspec.filesystem()`.

### The Error

```text
ftplib.error_perm: 530-Login failed. Re-enter your user name and password.
530  If this problem persists, contact your system administrator.

```
